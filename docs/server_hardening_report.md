# 图谱、文件日志与2核2GB部署加固结果

## 已完成

- 新关系及事件关系候选拒绝自环；按谓词检查人物／团体／项目／事件端点类型。
- 旧包保留原始哈希和ID，在派生投影隔离非法断言并输出计数，而非篡改原始事实。
- 明确固定人物称呼配置，同域内归一化显示/查询；真实更新目标仍绑定旧ID、版本及来源。
- 上下文裁剪统一计算可见源条目和图谱ID，保留边端点/support闭包；避免模型看到却无法合法引用。
- 草稿缓存增加图谱generation、配置与降级状态校验：即使dialog revision未变化，图谱更新也会使旧草稿失效。
- 图谱启用后的维护不再依赖include_story外层条件；同步和降级状态进入dfy.graph日志。
- 故事恢复与迁移改为流式前缀核验，不同时保留每个revision完整状态，仍保证两份投影验证通过后才修复。
- 复用收信处理中的同次snapshot，canonical图谱验证数据只保留可见目标；SQLite默认8MiB页缓存、FILE临时存储。
- UTF8文件日志支持日期与大小双轮转，14备份/10MiB可配；启动实际写入探针；运行期故障只安全告警，不在SMTP步骤随意抛异常。
- 无TTY缺凭据明确失败，不等待getpass；三入口共用凭据检查。
- 新增clock统一入口systemd模板，重启限流、专用用户/私有权限、资源限制和journal启动诊断。
- config/settings_example.json集中图谱身份/资源与日志调节参数。

全部测试离线，使用合成数据、临时目录、假模型和假SMTP。

合成流式恢复额外Python分配（tracemalloc，不含输入生成）：

| revision/事件数量 | 峰值MiB | 本机恢复耗时 |
|---|---:|---:|
| 200 | 0.553 | 1.699秒 |
| 600 | 1.494 | 15.079秒 |

这些不是总进程RSS、Linux服务器占用或长期性能保证。模型SDK、历史JSON、图片解码和任务载荷还会占用内存；需按部署清单在目标服务器观察。

对已有预览进行只读新投影核验：128事件保留，2条明确非法边被隔离（错误类型边和事件自环），人物节点从15归一到9，13条待整理仍如实保留。未改预览文件、源快照或调用模型。
